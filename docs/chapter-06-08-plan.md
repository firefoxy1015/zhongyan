## 代码改造顺序

1. **来源契约**
   - `StorySourceRef` 记录起止原著章、起止行和引用性质。
   - `quote` 必须能在所标原文行范围内规范化逐字匹配；改写必须标成 `adaptation`。
   - 自动测试核对章节标题、行范围、游戏章边界和逐字引文。
2. **章节注册表**
   - 用 `STORY_CHAPTER_IDS` / `SOLO_CHAPTER_IDS` 代替 3-5、1-5 的散落硬编码。
   - 存档解析、门禁、调试入口、BGM、SSR 路由测试全部消费同一注册表。
3. **资源账本**
   - 状态改为分账户：齐夏行动队、李尚武/章晨泽、老吕个人、已焚毁。
   - 场景只通过分账户 delta 改账；结算值用于校验而非覆盖计算结果。
   - 旧 v3 `daoCount` 档按已完成场景重建分账户正史账本（例如第 3 章拆为齐夏 2、李/章 1），不信任旧总数直接归入齐夏账户。
4. **章节数据与玩法**
   - 第 6 章：清账、年代矛盾、钟响陷阱、极道死亡、规则缺口、人形虫静默撤退、人猪入口。
   - 第 7 章：棋子概率 `74/99`、读取反应、强制赌命、逼出一黑一白、真假话嵌套问法、人猪赎罪。
   - 第 8 章：藏空面具、天堂口层级、血迹追踪、钟响物证、人兔残局重建、李尚武舍手救人、三问组队。
5. **静态资产**
   - 新立绘/场景图只新增版本文件，不覆盖旧角色。
   - 所有运行时引用必须进入通用 manifest，包含 SHA-256、尺寸、版本和来源说明。
   - 语音一段只生成一次；完整音色配置进入 input hash。返回角色继续使用锁定版本。
6. **动画与音频**
   - 每个关键正史事件使用独立动画 ID 和专属 CSS，不允许落到统一红线占位。
   - `skippableAfterMs` 真正控制按钮；动画结果在完成后才显示。
   - 6-8 章分别使用独立循环 BGM，关键动作使用本地 SFX；用户手势后播放。
7. **验收门禁**
   - `typecheck`、`lint`、全部单测、构建、`git diff --check`。
   - Playwright 验证 2→3→4→5→6→7→8 的 `fresh=1` 行为、刷新恢复和 URL 清理。
   - 桌面与 390×844 手机验证无裁头、无横向溢出、记录面板可滚动、按钮可达、音频请求成功。
